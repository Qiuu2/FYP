# 香港与新加坡 AI／生物医药大学专利采集包

从 Google Patents Public Data 补采2015—2025年已公开专利，输出港新大学专利逐年观察值、申请人待核查清单、逐族明细及年份差异。这里不采金融专利；未公开申请无法直接获得。2024—2025特别需要标注不完整。

## 已核查的历史数据

- `audit/historical_77_date_scope_differences.csv`：逐族保留本地条件首申日与大学名称补查的窗口内首申日；77个年份差异中，本地命中年份均较晚。两者衡量范围不同，并不因此能认定哪一个是真正全球优先权日。
- `audit/university_names_pending.csv` 与 `config/reviewed_aliases.csv`：3个疑似大学拼写已列出。尚未找到足够的逐件外部证据核实，标记为`pending`，**不会自动算入确认值**；只有人工复核并把status明确改为`confirmed`后才计入。
- `audit/audit_manifest.json`：历史输入摘要及SHA-256。先前AI 2025是另一批独立快照；历史2015—2024以2026-10-04查询为基准，不能把不同采集批次当作一次性快照。
- 现有主体分类和大学名称名单来源于既有研究底稿，部分为历史草稿而非逐件人工确认；应根据待核表继续复核，不要将全部标签当作已核实事实。
- GitHub版本只包含大学及公营机构的组织分类，不包含个人申请人分类。企业、个人等未覆盖名称默认显示为`unclassified`，而不会自动归为企业或零。

## 最容易的使用方法（Windows）

### 1. 先确认Python

打开 PowerShell，进入本目录，运行：

```powershell
py -3 --version
```

若无`py`，可以试 `python --version`。如果跳出Microsoft Store或提示路径无效，请安装Python 3.9或以上、关闭Windows应用执行别名，或使用实际存在的Python完整路径。**本包不需要创建虚拟环境，也不需要pip安装任何库。** 后面示例的`py -3`可换成真实Python可执行文件，例如 `& 'C:\实际路径\python.exe'`。

### 2. 在BigQuery运行查询

1. 使用有BigQuery权限的Google账号和项目，打开BigQuery网页。
2. 复制 `sql/university_patents_2015_2025.sql` 全文到查询编辑器。
3. **先检查预估扫描量与项目收费，再运行。** 本包不承诺免费；查询时间与费用取决于项目和数据量。
4. 导出**完整查询结果**为CSV，例如`university_raw.csv`。结果应包含一行`row_type=manifest`。如果网页限制行数，改用BigQuery的完整导出方式；只保存预览行会被校验拒绝。

查询含港新本地申请人及按名称筛选的大学候选，再导出这些家族在窗口内的逐件公开记录，包括CPC、申请人、地区、申请及公开日、优先权日与可用的发明人国家。筛选词和已有大学名称表均可能漏项，并非无条件全量。

### 3. 生成结果

```powershell
py -3 .\process.py --csv ".\university_raw.csv"
```

运行成功后 `results/` 包含：

- `年度大学专利.csv`：已确认数量、可能未识别数量及是否可用的观察值；`local`和`expanded`两套口径分开。
- `大学专利族明细.csv`：专利族、两种申请时间、公开件和大学名称。
- `申请人分类明细.csv`：全部候选家族申请人及现有机构分类；未纳入机构分类表的企业、个人等显示为未分类。原始导出和此明细可能含个人姓名，均保留在本地。
- `申请人待核查.csv`：疑似大学的未匹配名称；这不是已确认大学数量。
- `年份差异.csv`：同一族不同首申口径及采用的年份。
- `manifest.json`：输入、SQL、分类表的SHA-256、导出行数、采集时刻与最大公开日。来源输入可在复核时与之比对。

`usable_observed_count`为空表示存在可能影响该年数量的未分类申请人，不是零；已确认族若同时有其他未知申请人，仍会在待核表单独展示。全部数量受检索与别名覆盖限制，0代表**本查询识别数为0**，不是证明现实中没有专利。

### 4. 分类复核与复跑

在 `config/reviewed_aliases.csv` 添加或修改名称、城市（`hk`/`sg`）、大学、层级（`A`大学本体，`B`异地分支）及证据链接；只有`status=confirmed`会参与分类。先确认后修改，保存UTF-8 CSV，重新执行上面的处理命令。`pending`不计入已确认值。名称完全匹配；新名称如果不在既有候选查询范围内，仍需调整SQL再采。

如需在本机额外分类其他申请人，可创建`config/private_sectors.csv`，表头为`assignee,sector`；文件不会由Git跟踪。个人姓名或个人分类只放本地，不要公开上传。

## 口径和适用边界

- `local`：同一公开件中识别到地区代码为HK/SG的大学申请人且命中行业CPC，按最早符合该条件的申请日计年。
- `expanded`：基础口径另加匹配大学本体名称的全球候选。若有本地条件命中，沿用本地首申年份；否则采用2015—2025窗口内该族最早申请年。两口径所表示的地域范围不同，不能简单称新增数为本地漏计。
- 原始逐件输出还带Google记录的`priority_date`，但数据窗口有限、字段可能缺失，不能直接称为经验证的全球最早优先权。`priority_date_observed`仅是已导出公开件的可见最早优先权。
- 同一族可同时属于AI、生物及多个地区／主体，不可把分类总数直接相加。家族内不同时间的多个申请人不等于同一专利共同申请或真实合作。
- CPC沿用原项目宽口径：AI为G06N、G06V、G10L、G06F40、B25J；生物为A61、C12、C07K、C07D、G16H。匹配CPC不等于该专利必然是AI或医药领域的核心创新。
- 只包含已公开、被数据源及候选规则覆盖的公开记录；可能漏掉名称变体、申请人变更及特定地区的申请，不等于全年申请总量。较近年份不使用插值或预测填满。
- 发明人国家不等于确切研发城市；专利申请也不等于许可、商业化或研究人才流动。
