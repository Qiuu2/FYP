## 一、phase 差额结案

`ct_phase_probe.py` 实测 hk/2024Q1（totalCount = 109，取回 109 条）：

| phases 取值 | 条数 |
|---|---:|
| NA | 73 |
| **没有 phases 字段** | **14** |
| PHASE3 | 12 |
| PHASE2 | 7 |
| EARLY_PHASE1 | 1 |
| PHASE1 | 1 |
| PHASE4 | 1 |

单值 95 · **多值组合 0** · 无字段 14 · 合计 109

**结论**：差额 14 条是「根本没有 `phases` 字段」，不是多值组合。
组长此前推断「线索指向多值组合」**不成立**——实测多值组合数为 0。

**后果**：`AREA[Phase]xxx` 枚举六个取值无论如何都筛不到这 14 条。
全量重采若沿用逐期别 count，会系统性少计约 13%。

**采集方案二选一**：
- (a) 六个期别之外，用 `totalCount − Σ(六期别)` 倒推「无字段」档
- (b) 改为拉全量记录后本地归类（`ct_phase_probe.py` 已证明单页可取回 109 条）

(b) 更稳，且与 (a) 相比可留下原始记录备查。

## 二、字段缺失 bug（同一病根，已出现两次）

### 2.1 `jobs_panel_fetch.py` 漏抓岗位

賈贇核对 Animoca 职位板：

| 来源 | 岗位数 |
|---|---:|
| Lever API JSON | **13** |
| 其中写了 `commitment` 字段的 | 11 |
| 我们脚本抓到的 | **11** |
| 官网 careers 页 | 17（多出 4 个为 21 天短工，不在 API） |

脚本漏了 2 个——推定是依赖 `commitment` 字段存在，无此字段的记录被丢弃。

### 2.2 与 J4 同源

两处都是**假设某个可选字段总是存在**：

- `phases` 缺失 → 14 条试验筛不到
- `commitment` 缺失 → 2 个岗位抓不到

**通则**：外部 API 的字段多为可选。解析时须显式处理缺失，
并在产物中保留「字段缺失」这一档，不得静默丢弃。
