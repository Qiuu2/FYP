# 数据入库流程（六步，每个数据包裹都走一遍)

1. **采集**：脚本或人工下载 → 文件落到 `raw/`（原始响应，不做任何修改；人工整理类数据在表格中逐行带 source_url 列）。
2. **登记**：立刻 `python scripts/manifest.py add raw/<文件> --url ... --query ... --by <姓名>`。忘登记的文件会被 `verify` 拦下。
3. **清洗**：脚本从 raw/ 生成 `clean/<名称>_by_year.csv` 等（命名必须匹配 qa_check.py 已登记的 schema 后缀；新类型先登记 schema）。
4. **溯源**：为每个 clean 文件写同名 `.prov.json`：
   ```json
   {"manifests": ["hk_ai_by_year.json.manifest.json"],
    "script": "scripts/collect_all.py#part2",
    "created_utc": "2026-09-01T12:00:00+00:00"}
   ```
5. **校验**：`python scripts/manifest.py verify && python scripts/qa_check.py` 全绿才允许 commit。
6. **复核**：模块完成后，由非采集者抽 5% 数据点对照 manifest 里的 URL 核对，在 commit message 写「R4复核：<姓名>」。

边界模糊的公司归业 case：写入 `config/company_pending_cases.csv`（公司、证据、裁决、裁决人、日期），组会拍板后生效——裁决历史即附录 B 的审计轨迹。
