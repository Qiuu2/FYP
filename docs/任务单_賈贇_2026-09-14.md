## J4｜临床试验按 phase 重采　⏰ 9/26　⏱ 半天

**为什么**：IDI 商业维目前**没有有效的季度指标**。现有 `clinicaltrials_by_quarter.csv`
只有不分期的 `count`，测的是「有多少试验在做」，不是「离商业化多近」。
**Phase 3 进入数**是「接近上市」的合理代理（Phase 1 是研究、Phase 3 是上市前），
能让 biomed 的商业维至少有一个指标。

⚠️ **诚实交代它的天花板**：这只救得了 biomed。fintech 的商业维只有香港侧有牌照数、
ai 的商业维**结构性无源**。所以补完 phase 之后，商业维在六个单元上仍然不齐备，
它只能用于**单元内时序**（biomed 自己跟自己比），不能用于跨单元比较。
你不用为这个结果负责——先把数拿到。

### 现有调用长这样（`scripts/collect_all.py` 的 `mod_clinicaltrials_q`）

```python
http_get("https://clinicaltrials.gov/api/v2/studies",
         {"query.locn": term, "countTotal": "true", "pageSize": 1,
          "filter.advanced": f"AREA[StudyFirstPostDate]RANGE[{d0},{d1}]"})
```

### 候选改法（⚠️ 语法未经官方文档确认，请先验证再跑全量）

```python
"filter.advanced": f"AREA[StudyFirstPostDate]RANGE[{d0},{d1}] AND AREA[Phase]PHASE3"
```

我查不到 ClinicalTrials.gov API v2 的官方文档页（是 SPA，抓不到正文），
**所以 `AREA[Phase]` 这个字段名和 `PHASE3` 这个取值我不敢写死**。请你先做三步验证：

**第 1 步（最重要，先做这个）· 陷阱检查**
故意写一个不存在的字段：`AREA[NotAFieldXYZ]FOO`，看 API 的反应。
- 报错 → 好，说明写错了会被拦，后面的验证可信
- **静默返回全量 count** → ⚠️ **危险**：filter 写错时不会报错，只会悄悄失效。
  那么「加了 phase 之后数字变了」也不能证明 filter 生效，必须换别的办法确认（见第 3 步）

**第 2 步 · 加总检查**
对同一个季度分别取 PHASE1 / PHASE2 / PHASE3 / PHASE4 / NA 的 count，
与不带 phase 的总数比。应当 **各 phase 之和 ≥ 总数**（一个试验可能同时标 PHASE1|PHASE2，会被重复计）。
- 若某个 phase 返回 **0** 或 **等于总数** → 语法没生效
- 若和远小于总数 → 取值枚举写错了（可能不叫 PHASE3）

**第 3 步 · 落地核对**
随便挑 3 个返回的试验，去 ClinicalTrials.gov 网页打开，看页面上的 Phase 是不是你筛的那个。
这一步能绕过第 1 步的陷阱，是最硬的证据。

**产物**：`raw/clinicaltrials_phase_by_quarter.csv`（列：`city,quarter,phase,count`）＋ manifest。
manifest 的 `query_or_method` 里请**写清最终确认可用的完整 filter 字符串**，以及你在第 1–3 步看到了什么。

**如果三步验证下来发现 API 不支持按 phase 筛** —— 那就**停下来回报**，不要硬凑。
那种情况下 IDI 商业维就是没有指标，这本身是一个要写进正文的结论。
